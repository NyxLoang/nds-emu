# 模拟器是什么？（零基础）

## 一句话

模拟器不是“魔法播放器”，而是一个 **普通 C 程序**：它假装自己是一台 Nintendo DS，按规则执行游戏卡带里的指令，并把结果画到电脑窗口上。

## 真机在干什么

真机上的 CPU 每秒做无数次同样的三步：

1. **取指**：从内存某个地址读出一个数字（指令）
2. **译码**：看这个数字表示“加”“跳转”还是“写内存”
3. **执行**：改寄存器，或改内存里的数据

模拟器做的事一模一样，只是“CPU”和“内存”都变成了我们自己写的代码和数组。

```
while (还在运行) {
    指令 = 从内存读(PC);   // 取指
    看懂指令是什么;         // 译码
    按规则改状态;           // 执行
    PC 指向下一条;
}
```

## 几个必须认识的词

### 十六进制

电脑里常用 16 进制写地址和机器码，前缀 `0x`：

- `0x10` = 十进制 16
- `0xFF` = 255
- `0x02000000` = NDS 主内存附近的一个典型地址

### 字节 / 半字 / 字

| 名称 | 大小 | 常见用途 |
|------|------|----------|
| 字节 (byte) | 8 位 | 最小读写单位 |
| 半字 (halfword) | 16 位 | Thumb 指令、部分像素 |
| 字 (word) | 32 位 | ARM 指令、寄存器宽度 |

### 小端序（little-endian）

一个 32 位数 `0x12345678` 存在内存里时，**低地址先放低字节**：

```
地址+0: 78
地址+1: 56
地址+2: 34
地址+3: 12
```

NDS 的 ARM CPU 就是小端。我们的 `bus_read32` 必须按这个规则拼起来。

更完整的十六进制与字节序说明（含大端对比、`bus_read/write` 拼接）见 [docs/00b](00b-hex-endianness.md)。

### 寄存器 vs 内存

- **寄存器**：CPU “手里的便签”，只有十几格（`r0`～`r15`），读写极快。
- **内存**：一大片字节数组。程序代码、变量、显存都在这里。
- **PC（r15）**：特别的寄存器，表示“下一条指令在哪”。

指令本身也是内存里的数字。例如某条 `B`（跳转）在内存里可能是 `0xEAFFFFFE` 这种值——对 CPU 来说它是命令，对文件来说它只是普通数据。

## 为什么先做“解释器”

有两种加速办法：

- **解释器**：一条条看懂并执行（我们先做这个，好懂、好调试）
- **动态翻译 / JIT**：把 ARM 指令临时翻成电脑自己的指令（后期才考虑）

学习向项目必须先解释器：你能单步打印“现在执行了哪条、寄存器变成了什么”。

## NDS 多出来的麻烦（先知道名字即可）

- **两颗 CPU**：ARM9（主）+ ARM7（辅助）——我们先认真做 ARM9
- **两块屏**：各 256×192——窗口里上下各一块
- **显存 VRAM**：程序往特定地址写颜色，屏幕上才有画面
