# NDS ROM 头（ARM9 / ARM7 关键字段）

## 一句话

一个 `.nds` 文件开头有一段**固定格式的头**，告诉模拟器三件事：ARM9 的代码在哪、该放进内存的哪里、有多大。ARM7 同样有一组对应字段。解析头，是装载的第一步。

## ROM 头长什么样

`.nds` 文件不是从第一字节就开始跑代码的。最前面的若干字节是"说明文字"，比如：

- `0x000`：`"NTR"` + 固定字节（任天堂的启动标记）
- `0x000` 附近还有游戏标题、游戏码、厂商码等（本阶段不关心）

我们只关心**代码在哪、装到哪、多大**，这些都在头里的固定偏移处，ARM9 和 ARM7 各一组：

| 字段 | 偏移 | 大小 | 含义 |
|------|------|------|------|
| ARM9 ROM offset | `0x020` | 4 字节 | ARM9 代码在文件里的起始偏移（从文件头开始数） |
| ARM9 entry address | `0x024` | 4 字节 | CPU 复位后从**哪个内存地址**开始执行 |
| ARM9 RAM address | `0x028` | 4 字节 | 这份镜像要装载到**哪个内存地址**（装载目的地） |
| ARM9 code size | `0x02C` | 4 字节 | 镜像有多大，要拷多少字节 |

ARM7 的四个字段在紧跟其后的偏移，结构完全一样：

| 字段 | 偏移 | 大小 | 含义 |
|------|------|------|------|
| ARM7 ROM offset | `0x030` | 4 字节 | ARM7 代码在文件里的起始偏移 |
| ARM7 entry address | `0x034` | 4 字节 | ARM7 CPU 复位后从哪个地址开始执行 |
| ARM7 RAM address | `0x038` | 4 字节 | ARM7 镜像要装载到哪个内存地址 |
| ARM7 code size | `0x03C` | 4 字节 | ARM7 镜像有多大 |

## 四个字段各是什么意思

### 1. ARM9 ROM offset（`0x020`）——代码在文件哪

`.nds` 文件里堆了很多东西：头、ARM9 代码、ARM7 代码、调色板、图标、数据……ARM9 代码不是从 0 开始，而是从 `0x020` 记录的**偏移**处开始。装载时我们从这个位置把数据读出来。

### 2. ARM9 entry address（`0x024`）——CPU 从哪里开始跑

CPU 复位后不知道去哪，需要头告诉它：**从 entry address 开始执行**。模拟器里这就是初始化 `PC` 用的值。

### 3. ARM9 RAM address（`0x028`）——镜像装到内存哪里

ROM 文件里的代码要**拷进内存**才能被 CPU 取指。拷到哪里？由 `0x028` 决定。NDS 上 ARM9 的代码通常装到 `0x02000000`（Main RAM）附近。

> 注意区分：**ROM offset 是"在文件里的位置"，RAM address 是"在内存里的位置"**。一个是读文件用，一个是拷内存用。

### 4. ARM9 code size（`0x02C`）——拷多少字节

从 RAM address 开始，把从 ROM offset 处读出的连续 `code size` 字节拷进内存，正好是一整段镜像。

## 小端

这四个字段都是 32 位整数，按**小端**存（复习 [docs/00b](00b-hex-endianness.md)）。读的时候要按 `b0 | b1<<8 | b2<<16 | b3<<24` 拼回来。这也是为什么头解析和 `bus_read32` 要写同一个拆拼逻辑。

## 自测（先别看答案）

1. ARM9 代码在文件里的位置由哪个字段、哪个偏移决定？
2. 装载时把镜像拷到内存的哪个地址？
3. 这四个字段在内存里怎么按字节排（大端还是小端）？

<details>
<summary>答案</summary>

1. ARM9 ROM offset，偏移 `0x020`。
2. ARM9 RAM address（`0x028`）指定的地址。
3. 小端，低地址先放低字节。

</details>
