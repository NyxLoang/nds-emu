# NDS 内存地图（最小集）

## 一句话

CPU 眼里没有「数组」，只有**一个巨大的地址空间**（0~4GB）。不同的地址区间对应不同的硬件——读到的是数据、颜色，还是什么都不做，全看地址落在哪段。`bus` 的职责就是：**给定地址，换算成某块内存数组里的偏移，再去读写**。

## 为什么地址是按区间分的

NDS 的 32 位地址空间（`0x00000000` ~ `0xFFFFFFFF`）由厂商划分成固定区间。同一段地址在**内存里**（Main RAM、VRAM），在**硬件寄存器里**（IO），或在**卡带里**（ROM），由地址的最高几位决定。

我们的模拟器先做三块（其余读 0 / 写忽略）：

| 区间起始 | 大小 | 名称 | 用途 |
|----------|------|------|------|
| `0x02000000` | 4MB | Main RAM（ARM9 主内存） | 程序数据、ARM9 镜像装载处 |
| `0x06000000` | 656KB | VRAM | 显存：程序往这里写颜色字，屏幕上才有画面 |
| `0x04000000` | 小段 | IO 寄存器 | 显示控制、按键等硬件开关（暂做桩） |

> 真机还有更多区间（`0x03800000` ARM7 内存、卡带空间等），本阶段只实现这三块，其它读 0、写忽略，**保证任意地址访问不崩**。

## 地址是怎么换算的

给一个总线地址 `addr`，bus 的换算逻辑是**区间命中**：

```
if addr 落在 [0x02000000, 0x02000000+4MB)：
    内存数组索引 = addr - 0x02000000   （区间基址相减得偏移）
    读写 main_ram[索引]

else if addr 落在 [0x06000000, 0x06000000+656KB)：
    索引 = addr - 0x06000000
    读写 vram[索引]

else if addr 落在 [0x04000000, 0x04000000+小段)：
    读返回 0，写忽略（IO 桩）

else：
    读返回 0，写忽略（未映射空间）
```

**核心思想**：每个区间就像一个「大数组」，`addr - 区间基址` 就是它在数组里的下标。这也是为什么 `ram=0x02000000` 装载时，镜像直接放进 `main_ram` 的开头。

## 宽度的换算

CPU 可以按三种宽度读写：

| 宽度 | 读写几个字节 | 地址含义 |
|------|--------------|----------|
| 8 位 | 1 个字节 | 直接读写 `arr[addr - base]` |
| 16 位 | 2 个字节 | 小端：低字节在低地址（复习 `docs/00b`） |
| 32 位 | 4 个字节 | 小端拼拆 |

例：往 `0x02000000` 写 32 位 `0x12345678`，小端下内存是：

```
main_ram[0] = 0x78
main_ram[1] = 0x56
main_ram[2] = 0x34
main_ram[3] = 0x12
```

## 自测

1. 地址 `0x02000100` 在 Main RAM 里的下标是多少？
2. 地址 `0x06000200` 在 VRAM 里的下标是多少？
3. 往 `0x02000000` 写 `0x12345678`（32 位），`main_ram[1]` 是多少？

<details>
<summary>答案</summary>

1. `0x100`（256）：`0x02000100 - 0x02000000`。
2. `0x200`（512）：`0x06000200 - 0x06000000`。
3. `0x56`：小端，`0x12345678` 的次低字节放在 `+1`。

</details>
