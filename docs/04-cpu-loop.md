# CPU 循环：取指 → 译码 → 执行（零基础）

## 一句话

CPU 一辈子只做一件事：**读 PC 指向的内存 → 拿到一条指令 → 看它想干什么 → 执行 → PC 前进，再读下一条**。这个循环叫「取指-执行循环」。

## 三个概念

### 1. PC（Program Counter，程序计数器）

- 就是 `r15`，一个普通得不能再普通的寄存器。
- 它保存**下一条要执行的指令的地址**。
- 每执行完一条指令，PC 大多会 +4（ARM 状态每条指令 4 字节）。

> 注意：ARM 里有一条历史包袱——执行指令时，PC 实际已经指向「当前指令 + 8」。阶段 3b 处理跳转指令时才会用到这个 +8，3a 阶段只做「PC += 4」的简单推进。

### 2. 取指（Fetch）

按 PC 的地址，从 bus 读 **32 位**（一个 ARM 指令字）。这就是阶段 2 的 `bus_read32` 派上用场的地方：

```
指令 = bus_read32(nds->bus, pc)
```

### 3. 译码 / 执行（Decode / Execute）

拿到 32 位机器码后，根据它的**位模式**判断是什么指令，再执行对应动作。

## 指令长什么样（ARM 32 位指令）

一条 ARM 指令是 32 位，CPU 靠**高几位**决定怎么理解它：

```
bit31-28: 条件码（1110 = 无条件 AL）
bit27-25: 指令大类（101 = 分支 B/BL）
```

例：`EAFFFFFE` 拆开看：

```
E A F F F F F E  (16 进制)
1110 1010 1111 1111 1111 1111 1111 1110
└┬┘ └─┬──┘ └────────────┬────────────┘
条件  大类=101(B)        24位立即数 = 0xFFFFFE
 AL                     （-1，即"跳 0 步"= 跳到自己）
```

- `1110` = 无条件执行（AL = Always）
- `101` = 分支指令（B / BL）
- 24 位立即数 `0xFFFFFE` 符号扩展后左移 2 位 = `-8`
- 跳转目标 = `PC + 8 + (-8)` = **PC 自己** → 死循环，原地打转

这正是 `mini.nds` 的 ARM9 入口 `0x02000800` 处的第一条指令：**无条件跳转到自己**。

## 三步走（阶段 3a 的全部内容）

```
r15 = 0x02000800          ← 3a.2：初始 PC = 镜像入口地址
loop:
  指令 = bus_read32(pc)   ← 3a.3：取指
  若是"跳自己"：原地打转    ← 3a.5：死循环识别
  否则：打印并计数          ← 3a.6：未实现指令
  pc += 4                 ← 3a.4：前进（没跳转时）
```

## 自测

1. PC = `0x02000800`，从这里 `bus_read32` 应取到多少？（`mini.nds` 入口）
2. 上面这条指令，跳转目标是它自己吗？为什么叫「死循环」？
3. 如果一条指令不是分支，执行完后 PC 加几？

<details>
<summary>答案</summary>

1. `EAFFFFFE`（`FE FF FF EA` 小端读回的字）。
2. 是。24 位立即数 = -1，跳转量 = -8，目标 = `PC + 8 - 8 = PC`，跳到自己 → 永远在原地，不执行新指令 = 死循环。
3. +4（ARM 状态每条指令 4 字节）。

</details>
