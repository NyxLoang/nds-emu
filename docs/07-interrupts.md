# 中断：CPU 被打断去跑处理程序（零基础）

## 一句话

**中断（Interrupt，缩写 IRQ）= CPU 正在干别的活，硬件突然喊「有急事」，CPU 停下当前
指令流，跳到一段专门的处理程序（handler）干完急事，再回来接着干。**

例子：NDS 每秒钟画面刷新 60 次（60fps）。每次刷新完一行/一屏，显示硬件都会发一个
「刷新完成」信号。游戏程序可以趁这个信号更新画面——如果不用中断，程序就得自己
不停检查「刷新完了没」，浪费 CPU；用了中断，程序只管干自己的，硬件会主动通知。

## NDS 中断的三个寄存器（ARM9 地址）

NDS 用一个「总开关 + 使能 + 挂起」三位一体的机制管理中断：

| 寄存器 | 地址 | 作用 | 读写规则 |
|--------|------|------|----------|
| **IME** | `0x04000208` | 总开关（Interrupt Master Enable） | bit0=1 才允许任何中断 |
| **IE**  | `0x04000210` | 各中断源使能（Interrupt Enable） | 某位=1 表示该中断被允许 |
| **IF**  | `0x04000214` | 挂起标志（Interrupt Flag） | 硬件置 1；**软件写 1 清除** |

每个中断源占一位。NDS 硬件 **VBlank 在 bit0**（bit3 是 Timer0）；21-B9h 起按硬件位修正。

```
IF bit  7   6   5   4   3   2   1   0
        …   …   …   …  TM0 …   …   VBlank
```

### 它们怎么配合

```
硬件发生了 VBlank（一帧画完）
   │  IF |= bit0（挂起位被置 1，无论使能与否）
   ▼
IF & IE & IME 都不为 0  → 中断真的发生（CPU 被叫走）
   │
软件在 handler 里「写 1 到 IF 的 bit0」→ 清除挂起位
   ▼
IF bit0 = 0 → 下次 VBlank 再重新置位
```

关键点：

- **IF 置位 ≠ 中断发生**。只有「IF 有挂起 **且** IE 使能 **且** IME 总开关打开」三者同时
  满足，CPU 才真的被打断。程序可以先看 IF 有没有置位（这叫**轮询 poll**），不一定用中断。
- **IF 的清除是「写 1 清 0」**：程序往 IF 里写 1 的那一位会被清掉，写 0 的位不受影响。
  这是硬件寄存器最常见的「读-改-写」陷阱——不能直接回写读到的值。

## 中断 vs 轮询

| 方式 | 程序怎么写 | 优点 | 缺点 |
|------|-----------|------|------|
| 轮询 | 循环 `LDR IF → 检查 bit0 → 没置位就继续转圈` | 简单，不需要改 CPU 模式 | 空转浪费周期 |
| 中断 | 配好 IME/IE，硬件自动打断 | 省电、及时 | 要处理返回地址/模式切换 |

本阶段（6.3/6.4）先实现**轮询能读到 VBlank 标志 + 检测到中断挂起**；
真正让 CPU 跳去 handler（进异常向量 `0x18`）留到阶段 10+。

## 本模拟器如何产生 VBlank

真机是显示硬件每帧自动置位。本模拟器用**指令计数近似**：
主循环每帧固定执行 N 条指令，N 条跑完就调 `io_set_vblank()` 把 IF 的 bit0 置 1。
于是程序里轮询 IF，行为就和真机一样了。

## 自测

1. 中断真正发生需要哪三个条件同时满足？
2. IF 里 VBlank 是第几位？怎么清除它？
3. 轮询和中断的区别是什么？本阶段实现了哪种？

<details>
<summary>答案</summary>

1. IF 挂起位=1、IE 使能位=1、IME 总开关 bit0=1，三者缺一不可。
2. bit0（值 `0x0001`）；往 IF 写 1 到该位即清除（写 0 不动）。
3. 轮询是程序自己循环检查标志；中断是硬件打断。本阶段实现轮询 + 最小挂起检测，
   不跳异常向量。
</details>
