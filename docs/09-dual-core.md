# 双核分工、共享内存与 IPC FIFO（零基础）

## NDS 为什么有两颗 CPU

NDS 机身里有两颗 ARM CPU，各司其职：

| CPU | 型号 | 主要分工 |
|-----|------|----------|
| ARM9 | ARM946E-S（67MHz） | 主处理器：跑游戏逻辑、3D/2D 渲染、读卡带 |
| ARM7 | ARM7TDMI（33MHz） | 协处理器：音频、触摸屏、Wi-Fi、电源管理 |

游戏里画面卡不卡、逻辑多复杂主要看 ARM9；声音、触摸、联网这些「后台」活交给 ARM7。
两颗核同时干活，各跑各的程序（`.nds` 里就分别存了 ARM9 镜像和 ARM7 镜像）。

## 共享内存：两颗核看同一块黑板

ARM9 和 ARM7 共享大部分内存（Main RAM `0x02000000` 等），就像两人对着同一块黑板写字：
A 写下一个数，B 立刻能读到。这是它们协作的基础。

ARM7 还有一块**自己专属的**内存：ARM7 WRAM（`0x03800000`，64KB），ARM7 的镜像就装在这里。

## IPC：两颗核怎么「对话」

两颗核不能直接互相「喊话」，需要一个中间媒介——这就是 **IPC（Inter-Process
Communication，进程间通信）**。NDS 的 IPC 最主要的形式是 **FIFO**。

### FIFO = 先进先出的传话管道

FIFO（First In First Out）是一条「排队管道」：先写进去的字，先被对方读出来。
每颗 CPU 各有一条**发送队列**和一条**接收队列**：

```
ARM9 写 SEND ──► [ from9 队列 ] ──► ARM7 读 RECV
ARM7 写 SEND ──► [ from7 队列 ] ──► ARM9 读 RECV
```

- ARM9 要传话给 ARM7：把 32 位字写进 `IPCFIFOSEND`（`0x04000188`），ARM7 从
  `IPCFIFORECV`（`0x04100000`）读出来。
- ARM7 传话给 ARM9 反之亦然。
- 每条队列深 **16 个字**：写满 16 个字还没人读，再写就溢出（错误）。

### 怎么知道管道空还是满

程序不能盲写盲读——写之前要先确认「管道没满」，读之前要先确认「管道不空」。
这靠 `IPCFIFOCNT`（`0x04000184`）里的状态位：

| 位 | 含义 |
|----|------|
| bit0 | 发送队列空（1=空，可以写） |
| bit1 | 发送队列满（1=满，不能写） |
| bit8 | 接收队列空（1=空，没数据可读） |
| bit9 | 接收队列满（1=满，有 16 字可读） |
| bit15 | 使能（0 时写 SEND 被忽略） |

经典轮询：发送前 `while (!(CNT & 0x0001))` 等空；接收前 `while (!(CNT & 0x0100))` 等非空。
（注意：ARM9 和 ARM7 各有自己的 CNT 实例，读到的是「自己」那一边的状态。）

### 也可以靠中断

不想空转轮询，可以开 FIFO 中断：发送队列变空、或接收队列变非空时，硬件把对应
CPU 的 IF 标志 bit17/18 置位（阶段 8 实现，真正进异常向量留到阶段 10+）。

## 本模拟器如何实现

- `arm_cpu_t` 加 `is_arm7` 标志复用同一套取指/执行逻辑；`cpu.h/c` 是接口，
  `arm9.c`、`arm7.c` 是各自功能文件。
- 总线加 `active_is_arm7`：单线程交错调度下，任一时刻只有一颗核访问总线，据此把
  FIFO 读写、中断寄存器按「谁在访问」分流。
- 中断寄存器（IME/IE/IF）也是**同址分流**：ARM9 和 ARM7 各有独立一套。

## 自测

1. ARM9 和 ARM7 各负责什么？它们怎么共享数据？
2. ARM9 要把一个字传给 ARM7，走哪几个地址？
3. 写 SEND 前应该检查 CNT 的哪个位？读 RECV 前呢？

<details>
<summary>答案</summary>

1. ARM9 跑游戏逻辑/渲染，ARM7 管音频/触摸/联网；共享 Main RAM 等内存（ARM7 另有
   专属 WRAM 0x03800000）。
2. ARM9 写 `IPCFIFOSEND`（0x04000188），ARM7 读 `IPCFIFORECV`（0x04100000）。
3. 写前查 bit0（发送空）、读前查 bit8（接收非空），即轮询 `CNT` 的状态位。
</details>
