# 背景、tile 与调色板（零基础）

## 一句话

真机 2D 画面不是「屏幕 = 一大块内存直接当像素」，而是**几层叠起来**的：每一层叫 **BG（背景）**，
BG 由很多 **tile（8×8 像素小方块）** 拼成，颜色则从一个 **调色板（palette）** 里查表得到。

## 屏幕是一层一层的

NDS 同时画 4 层 BG（BG0~BG3）+ 1 层 OBJ（精灵）。叠放顺序由**优先级**决定，优先级高的盖在低的上面。
像素为「透明」的地方，会露出它下面的图层——这就是为什么要「合成（compose）」：

```
OBJ（最上）
BG0
BG1
BG2
BG3
背景色（最下，谁都透明时看到的颜色）
```

## tile：8×8 的小方块

屏幕 256×192，可以切成 32×24 = 768 个 8×8 的小方块，每个小方块就是一块 **tile**。
游戏不想给每张图都存「整屏像素」，而是把画面拆成一块块 tile，重复的 tile 只存一次（省内存）。

- 一块 8×8 tile = 64 个像素。
- 16 色模式下，每个像素用 4 位表示（0~15），一块 tile 占 32 字节。
- 256 色模式下，每个像素用 8 位表示（0~255），一块 tile 占 64 字节。

## tilemap：一张「哪个位置放哪块 tile」的表

屏幕的每个 tile 格子里「放哪一块 tile」由 **tilemap（BG map）** 决定。它是一张表格，每项 16 位：

| 位 | 含义 |
|----|------|
| bit0-9 | tile 编号（指向字符数据里的第几块 tile） |
| bit10 | 水平翻转 |
| bit11 | 垂直翻转 |
| bit12-15 | 调色板编号（16 色模式下选哪 16 色） |

渲染时，对屏幕上的每个 tile 格子：查 tilemap 得到 tile 号 → 到字符数据里取那块 tile 的像素 →
按 tile 号对应的调色板把像素索引换成真颜色。

## 调色板：颜色查表

tile 里存的不是真颜色，而是**颜色索引**（编号）。真正的颜色在调色板里：

```
tile 像素 = 索引 3  →  查调色板第 3 项  →  得到一个 16 位 RGB555 颜色
```

- 调色板在内存 `0x05000000`（主引擎）与 `0x05000400`（副引擎）。
- 16 色 BG：每层选 16 色中的一块；索引 0 通常当作「透明」（露出下层）。
- 256 色 BG：直接 0~255 全用，索引 0 透明。

## 关键地址（阶段 9 用到的最小集）

| 用途 | 主引擎 | 副引擎 |
|------|--------|--------|
| 显示控制 DISPCNT | `0x04000000` | `0x04001000` |
| BG0 控制 BG0CNT | `0x04000008` | `0x04001008` |
| BG 图形/字符数据 | `0x06000000` | `0x06200000` |
| BG 调色板 | `0x05000000` | `0x05000400` |

- 字符数据地址 = `0x06000000 + BGxCNT.字符基址块 × 16KB`
- tilemap 地址 = `0x06000000 + BGxCNT.屏幕基址块 × 2KB`

## 位图模式（不拆 tile）

有些模式（「扩展位图」）不拆 tile，直接把 VRAM 当一整块像素（每像素 16 位 RGB555 直色）。
这种最简单，适合「先让真模式能出图」，阶段 9.3 先做它，9.4 再做真正的 tile 模式。

## 自测

1. 一块 8×8 的 16 色 tile 占多少字节？
2. tilemap 里一项的 bit0-9 是什么？
3. tile 像素里存的是真颜色还是索引？真颜色在哪？
4. 为什么需要「合成」？

<details>
<summary>答案</summary>

1. 64 像素 × 4 位 = 256 位 = 32 字节。
2. tile 编号，指向字符数据里要放的那块 tile。
3. 存的是颜色索引；真颜色在调色板（`0x05000000` 主 / `0x05000400` 副）。
4. 因为多层叠放，透明像素要露出下层，最终画面是各层按优先级合成出来的。
</details>
