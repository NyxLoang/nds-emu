# 阶段 10 短文：为什么还需要这些指令

阶段 3b 只实现了 ARM 指令集的一小部分（`MOV/ADD/SUB/CMP/LDR/STR/B/BL/BX/AND/ORR/EOR`）。
它们足以驱动手写的「伪程序」（写 VRAM、清屏、画矩形），但**真实游戏/BIOS 生成的机器码**
会大量用到下面这几类指令。缺失任意一类，真码就会在对应的机器码处被当作「未实现」跳过，
导致寄存器值错乱、跑飞。

## 1. 移位操作数（`LSL/LSR/ASR/ROR` 作为第二操作数）

ARM 没有独立的移位指令——移位是「免费」挂在数据运算的第二操作数上的：

- `ADD r0, r1, r2, LSL #2` = `r0 = r1 + (r2 << 2)`（数组下标 ×4 取元素，极其常见）
- `MOV r0, r1, LSL #16` = 组装 32 位立即数的高半字

真实代码几乎每条 `ADD/SUB/MOV` 都可能带移位，若忽略移位，计算全错。

## 2. 更多数据处理（`MVN/BIC/ADC/SBC/RSB/RSC/TST/TEQ/CMN`）

- `MVN`（取反）+ `BIC`（位清除）用于位掩码操作。
- `TST/TEQ`（与/异或只置标志）用于「按位测试再跳转」。
- `CMN`（加比较）用于「比较负值」。
- `ADC/SBC/RSC` 用于 64 位大数加减（多字算术）——crypto/解压代码常用。

## 3. `MRS` / `MSR`（读/写 CPSR）

- `MRS r0, CPSR`：读当前状态（含 N/Z/C/V 标志、中断使能位、模式位）。
- `MSR CPSR_c, r0`：写控制位（开关 IRQ/FIQ、切换处理器模式）。

真实程序启动时必经 `MSR CPSR_c, #模式` 切特权模式、`MRS` 读回标志，缺了它无法正确
进入中断处理、也无法正确判断条件分支。

## 4. `LDM` / `STM`（含 `PUSH/POP`）

函数调用/返回的标准做法：

```
PUSH {r4-r11, lr}    ; STMDB sp!, {r4-r11, lr}  保存现场
...                  ; 函数体
POP  {r4-r11, pc}    ; LDMIA sp!, {r4-r11, pc}  恢复现场 + 返回
```

编译器生成的**每一个**非叶函数开头/结尾都是 `PUSH/POP`，缺了它连函数调用都进不去。

## 5. 乘法（`MUL/MLA` + 长乘 `UMULL/UMLAL/SMULL/SMLAL`）

- `MUL r0, r1, r2` = `r0 = r1 * r2`
- `MLA r0, r1, r2, r3` = `r0 = r3 + r1 * r2`
- 长乘产生 64 位结果（哈希、定点运算、音视频解码）。

## 6. 字节/半字访存（`LDRB/STRB/LDRH/STRH/LDRSB/LDRSH`）+ 变址模式

阶段 3b 只有 32 位 `LDR/STR` 立即偏移。真实代码处理字符串/像素/结构体字段时：

- `LDRB`（无符号字节）、`LDRSB`（符号扩展字节）、`LDRH`（半字）、`LDRSH`（符号扩展半字）。
- 前/后变址、寄存器偏移（`LDR r0, [r1, r2, LSL #2]`）——数组访问的标准形式。

## 7. `SWI`（软件中断 = BIOS 调用入口）

NDS 游戏调用系统服务（除法、开方、内存拷贝、解压等）的方式就是 `SWI <编号>`。
`SWI` 是下一阶段「BIOS HLE」的地基——先要能识别并记录编号，才能拦截分发。

## 8. `SWP`（原子交换）与 `MRC/MCR`（协处理器访问）

- `SWP r0, r1, [r2]`：内存与寄存器原子交换（信号量/锁）。
- `MRC/MCR p15, ...`：访问 CP15 协处理器——游戏启动时写 CP15 控制寄存器（cache/MMU）。

---

**结论**：阶段 10 的目标不是「多实现几条指令」，而是**把 ARM 指令集补到「真实机器码能
跑起来」的程度**。补完之后，下一步才能接 BIOS HLE（阶段 11），让真正的 `.nds` 启动。
