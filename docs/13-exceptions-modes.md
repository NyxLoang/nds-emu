# 阶段 12 短文：特权模式、CPSR 模式位、异常向量表

阶段 11 用 HLE 在 `SWI` 指令处「拦截并直接调 C 函数」，绕过了 ARM 真正的异常机制。
阶段 12 要补上这套机制：让 `SWI`、`IRQ`、未定义指令、访存中止等**异常**走真机路径——
保存状态 → 切模式 → 跳异常向量 → 处理 → 恢复返回。这是让真实游戏的中断处理代码
（用 `MSR CPSR_c, #模式` 切态、写中断向量表、`LDM` 恢复现场）正确运行的前提。

## 1. 特权模式（Processor Modes）

ARM 有 7 种运行模式，由 CPSR 的低 5 位 `M[4:0]` 决定：

| M[4:0] | 模式 | 说明 |
|--------|------|------|
| 0b10000 (0x10) | User | 非特权用户模式（普通程序） |
| 0b10001 (0x11) | FIQ | 快速中断 |
| 0b10010 (0x12) | IRQ | 普通中断 |
| 0b10011 (0x13) | Supervisor (SVC) | 复位 / SWI 进入 |
| 0b10111 (0x17) | Abort | 取指/数据中止 |
| 0b11011 (0x1B) | Undefined | 未定义指令 |
| 0b11111 (0x1F) | System | 系统模式（与 User 同寄存器组，但特权） |

除 User 外的 6 种都是**特权模式**，每种都有自己的**私有（banked）寄存器**和
**SPSR（Saved Program Status Register）**，用于进入异常时保存被打断前的 CPSR 与现场。

> 阶段 10.4 里 `cpu.h` 只有一个 `spsr`；阶段 12.3 把它扩成 `spsr[5]`（每特权模式一份）。
> 阶段 10.4 的 `msr_write` 里「始终保护模式位 bit4-0」的注释，正是为阶段 12 的模式切换留的口。

## 2. CPSR 位布局

| 位 | 含义 |
|----|------|
| 31-28 | 条件码 N / Z / C / V |
| 27-8 | 保留（部分含 J/Q/GE，NDS 基本不用） |
| 7 | **I**：IRQ 禁止位（1=禁止 IRQ） |
| 6 | **F**：FIQ 禁止位（1=禁止 FIQ） |
| 5 | **T**：Thumb 状态（阶段 3b.11 暂缓，恒 0） |
| 4-0 | **M[4:0]**：模式位 |

阶段 3b/10 只用了 N/Z/C/V；阶段 12 起要用 I/F 位做中断屏蔽、用 M[4:0] 做模式切换。

## 3. 异常向量表

每种异常有固定入口，向量表基址固定（NDS 上 ARM7 用低向量 `0x00000000`，ARM9 用高向量
`0xFFFF0000`，ARM9 的基址可由 CP15 c1 控制）：

| 偏移 | 异常 | 进入模式 | 说明 |
|------|------|---------|------|
| 0x00 | Reset | SVC | 复位 |
| 0x04 | Undefined Instruction | Undefined | 未定义指令 |
| 0x08 | SWI | SVC | 软件中断（阶段 11 HLE 之前拦截） |
| 0x0C | Prefetch Abort | Abort | 取指中止 |
| 0x10 | Data Abort | Abort | 数据中止 |
| 0x14 | Reserved | — | 保留 |
| 0x18 | IRQ | IRQ | 普通中断 |
| 0x1C | FIQ | FIQ | 快速中断 |

每条向量处通常是一条跳转指令（如 `B handler`），跳到真正的处理程序。

## 4. 异常进入 / 返回的硬件动作

**进入异常**（以 IRQ 为例）：
1. `SPSR_<新模式> = CPSR`（保存被打断前的状态）。
2. 改 CPSR 模式位到新模式的 `M[4:0]`。
3. 按异常类型关中断：IRQ/FIQ 入口置 `I`（FIQ 额外置 `F`）。
4. `LR_<新模式> = 返回地址`（不同异常偏移不同：SWI/未定义 = 当前 PC+4，
   IRQ/FIQ = PC+4，Prefetch/Data Abort = PC+8 之类，具体按流水线阶段）。
5. `PC = 向量地址`（跳 handler）。

**返回异常**：真机用带 `S` 的指令恢复 CPSR 并跳回：
- `SUBS pc, lr, #4`（IRQ/FIQ，因为进入时 PC 还没走到的那条指令要补回）
- `MOVS pc, lr`（SWI/未定义）
- `LDM sp!, {..., pc}^`（块搬移的 `^` 同时恢复 SPSR→CPSR，多用于完整现场恢复）

> 阶段 10.5 已实现 `LDM/STM`，但 `^`（恢复 SPSR）当时未做；阶段 12.3 补齐。

## 5. 与我们模拟器的衔接（阶段 12 分步）

1. **12.2** 异常向量：`cpu.h` 增加 `vector_base`（ARM9=0xFFFF0000 / ARM7=0x00000000，
   或统一先按可配置基址）；`exec_step` 检测到 SWI/未定义等异常时，做「保存 SPSR → 切模式 →
   写 LR → 跳向量」。
2. **12.3** 模式与 SPSR：`cpu.h` 的 `spsr` 扩为 `spsr[5]`；`msr_write` 允许写模式位
   （去掉 bit4-0 保护）；MRS/MSR 按当前模式取/存对应 SPSR；`LDM/STM` 补 `^` 恢复 SPSR。
3. **12.4** CP15：`cpu->cp15[16]` 从「纯桩」升级为可读写控制寄存器（c1 的向量基址选择、
   cache/MMU 使能位），保证游戏写 CP15 不崩。
4. **12.5** IRQ 真实响应：`cpu_step` 开头检查 `IF & IE & IME` 且 CPSR 的 `I` 未置位，
   满足则走 IRQ 异常向量进 handler，handler 返回后继续被打断的代码。

> 阶段 11 的 BIOS HLE 仍在**异常向量之前**拦截 SWI（先判 HLE 已知函数，未知号才落回
> 阶段 12 的 SWI 异常向量）；这样既有 HLE 的高效，又给阶段 12.2 的 SWI 向量留了真机路径。
> 具体拦截顺序在 12.2 实现时敲定。

---

**结论**：阶段 12 把阶段 10 的 `spsr` 桩、阶段 11 的 HLE 拦截，升级为**完整的异常机制**——
模式切换、SPSR 保存/恢复、异常向量跳转、CP15 控制寄存器、IRQ 真实响应。完成后，
真实游戏的中断处理代码（而非我们手写的伪程序）就能在模拟器里正确进出 handler。
