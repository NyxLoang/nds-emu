# 16 — NDS 卡带命令协议（ROMCTRL / AUXSPICNT / CARD_COMMAND / CARD_DATA）

阶段 15 预习短文。目标：让游戏在**运行时**通过卡带总线读取 ROM 数据（而不是靠装载时
一次性把镜像拷进 RAM）。这是「顺畅玩商业 .nds」的关键一步——真实游戏几乎不会把整个
ROM 一次性读进内存，而是在游戏过程中按需从卡带流式读取（关卡、贴图、音频、存档等）。

## 1. 为什么阶段 1 的「一次性装载」不够

阶段 1/8 的做法是：解析 ROM 头 → 把 ARM9 镜像拷进 Main RAM、把 ARM7 镜像拷进 WRAM。
这只适用于 **homebrew**（整个程序就几十 KB）。商业游戏动辄几十 MB，而：

- Main RAM 只有 4MB，ARM7 WRAM 只有 64KB；
- 游戏运行时需要不断读新的关卡/资源数据；
- 因此真实游戏通过**卡带总线寄存器**按需读 ROM，就像 CPU 读内存一样。

## 2. 卡带总线寄存器（NDS7 与 NDS9 同址）

卡带总线由 ARM7 主控（ARM9 也能访问同一组寄存器）。地址在 IO 区 `0x040001A0` 起，
数据端口在 `0x04100010`（IO 区之外，与 IPC FIFO RECV `0x04100000` 类似）：

| 地址 | 宽度 | 名字 | 作用 |
|------|------|------|------|
| `040001A0h` | 2 | AUXSPICNT | 卡带 SPI/ROM 控制（bit15=使能，bit13=32 位传输模式） |
| `040001A2h` | 2 | AUXSPIDATA | 卡带 SPI 数据（EEPROM 等串行设备用） |
| `040001A4h` | 4 | ROMCTRL | 卡带总线时序/控制 + 状态（bit23=数据就绪 DRQ） |
| `040001A8h` | 8 | CARD_COMMAND | 8 字节命令输出（`040001A8`..`AF`，**大端**） |
| `040001B0h` | 4 | KEY2 种子 0 | 加密种子（阶段 14 KEY2 透明于软件，本阶段忽略） |
| `040001B4h` | 4 | KEY2 种子 1 | 加密种子（同上，忽略） |
| `04100010h` | 4 | CARD_DATA | 卡带数据端口（读 4 字节，自动推进） |

> 命令/参数字节是**大端**：命令第一个字节（MSB）在最小地址 `040001A8h`。这与 CPU 的
> 小端访存相反——所以用 8 位写命令时，字节顺序「看起来是反的」。

## 3. ROMCTRL 关键位

```
bit23    Data-Word Status（只读）：0=Busy，1=Ready/DRQ（有数据可读）
bit24-26 Block size：0=None，1=0x200，2=0x400 … 6=0x4000，7=4 字节
         （melonDS NDSCart：0x100 << n；早期文档写成 0x100 << (n-1) 有误，
          B9zo 已按 melonDS 修正，FFXII 块字段 1 实为 0x200）
bit31    Start/Activate（写 1 触发命令，锁存 CARD_COMMAND 并开始传输）
```

对模拟器而言，读数据的核心是：**写 ROMCTRL bit31 启动 → 轮询 bit23 变 1 → 从 CARD_DATA
读 4 字节**（每次读自动前进 4 字节）。

## 4. 卡带命令（CARD_COMMAND 的第一个字节）

| 命令 | 名字 | 说明 |
|------|------|------|
| `B7h` | GetData | 读 ROM：`B7 addr[31:24] addr[23:16] addr[15:8] addr[7:0] 00 00 00` |
| `B8h` | GetData(续) | 同上（用于 KEY2 加密区 / 4 字节对齐读） |
| `90h` | Get ROM Chip ID | 返回 4 字节芯片 ID（读 CARD_DATA） |
| `00h` | Get Header Chip ID | 读卡带头 16 字节 |
| `3Ch` | Activate KEY1 | 用 8 字节魔数激活 KEY1 加密（阶段 14 已内建） |

阶段 15 只需实现 `B7`/`B8`（读数据），其余命令留待后续阶段。

## 5. 读 ROM 的典型流程（游戏侧）

1. 写 `CARD_COMMAND` 8 字节：`B7 <addr32 大端> 00 00 00`。
2. 写 `ROMCTRL`（含 bit31=1，可能含块大小/时钟位）→ 硬件开始传输。
3. 轮询 `ROMCTRL` bit23 直到变 1（数据就绪）。
4. 从 `CARD_DATA`（`0x04100010`）读 4 字节，地址自动 +4；重复直到读完。
5. （可选）等待「卡带数据就绪」中断（ARM7 IF bit24 / 传输完成 bit19）。

## 6. DMA 读卡带（真游戏典型装载路径）

逐字轮询太慢，真实游戏用 **DMA + 卡带触发源**：把 DMA 通道的源地址设为 `CARD_DATA`
（`0x04100010`）、目标设为 RAM、触发源设为「卡带 DRQ」（start mode = 5），启用后 DMA 会
在每次卡带数据就绪时自动搬 4 字节。模拟器里卡带传输是「瞬时」的，因此触发一次即可把
整个块搬完。

相关 DMA 控制位（详见阶段 7 的 `src/io/dma.h` 扩展）：

```
CNT bit25  Repeat（重复模式，VBlank/HBlank 用）
CNT bit27-29 Start mode：0=立即 1=VBlank 2=HBlank 5=卡带 DRQ
CNT bit30  IRQ（搬运结束置 IF 对应位）
CNT bit21-22 目的地址控制：0=增 1=减 2=固定
CNT bit23-24 源地址控制：同上
```

## 7. 本阶段验收口径

- **15.2**：写命令 + 启动后，从 CARD_DATA 能按序读回 ROM 里对应地址的数据。
- **15.4**：DMA（卡带触发源）能从 ROM 把数据搬进 RAM，结果正确。
- **15.5**：自制 ROM → 卡带命令读 + DMA 搬移，走通完整装载路径。
